# 自然言語検索デモ用の1,000記事

MT形式の[jev-demo-1000.txt](jev-demo-1000.txt)をインポートして使う。20テーマ × 10種類の状況 × 5種類の運用体制で、1,000件の架空の記事を作成した。実在の組織の事例や実際の製品価格を示すものではない。

## ファイル

| ファイル | 用途 |
| --- | --- |
| [jev-demo-1000.txt](jev-demo-1000.txt) | MTにインポートするデータ。UTF-8・LF・1,000記事、約1.9 MB |
| [manifest.csv](manifest.csv) | 各記事の特徴と照合用ID。表計算ソフト向けにUTF-8 BOM付き |
| [queries.json](queries.json) | 自然文の検索例10件と、作成時に想定した該当記事ID |
| [generate_dataset.py](generate_dataset.py) | 同じデータを再生成するスクリプト。Python 3.9以降・標準ライブラリのみ |

記事本文はすべて `BODY` にHTMLの段落として入っている。`EXTENDED BODY`、`EXCERPT`、`KEYWORDS` は空。HTMLタグを除いた本文は423〜616文字、平均約525文字。長文の限界試験より、条件判定を比較しやすい短めのデモを想定している。

タイトルと `BASENAME` に識別子を入れている。たとえば `JEV-0006` は `jev-demo-0006` に対応する。CSVのIDはMTのDB上の記事IDとは別物。

判定用のラベルはCSVだけに入れた。「料金の記載がない」というラベルや、そのことを説明する文章を記事本文に混ぜていない。

## MTへの取り込み

1. デモ用サイトの記事インポートで、Movable Type形式を選択する。
2. `jev-demo-1000.txt` を指定し、文字コードをUTF-8にする。
3. インポートする記事の所有者に既存のユーザーを指定する。ファイルに `AUTHOR` は含めていない。
4. 1,000記事と、テーマごとの20カテゴリーが作成される。

全件 `STATUS: Draft`（下書き）。公開済みの記事だけに検索を絞ると表示されない。日付は2024-01-01〜2026-08-15に分散しており、状況の種類と新旧が同じ順にならないようにしている。

JevプラグインにOpenAIキーが設定済みなら、インポート時の保存でもembedding生成が走る。後からCLIで生成する場合は、OpenAIキーが未設定の状態で取り込み、その後キーを設定してMTルートから次を実行する。

```sh
perl tools/Jev/build-index --blog-id デモ用サイトのID --type entry
```

## データの特徴

各テーマは50記事。同じテーマ・運用体制で状況だけが異なる記事を作り、単語の一致と条件への適合の違いが見えるようにした。

| 状況コード | 状況 | 件数 |
| --- | --- | ---: |
| S01 | 導入後に実際の問題が発生し、解決。料金の記載あり | 100 |
| S02 | 導入後に実際の問題が発生し、解決。料金の記載なし | 100 |
| S03 | 導入済みで問題なし。「困ったことはなかった」と明示。料金の記載なし | 100 |
| S04 | 検討段階。問題は想定であり、まだ本番導入していない | 100 |
| S05 | 機能は合うが、予算に収まらず導入を見送った | 100 |
| S06 | 導入済みで問題なし。料金の記載あり | 100 |
| S07 | S03と同じ本文の末尾にだけ料金の段落を追加 | 100 |
| S08 | 「手が止まる」「仕事が積み上がる」と表現した実際の問題と解決。料金の記載なし | 100 |
| S09 | 当初は「問題なし」と報告したが、本番で問題が判明。まだ解決していない | 100 |
| S10 | 実運用は問題なし。研修用の架空のトラブルを引用している | 100 |

5種類の運用体制は、4人・二拠点兼務、7人・スマートフォン利用、12人・紙の確認表併用、18人・曜日で担当交代、25人・新任者と経験者の混成。「5人以下」「スマートフォンで確認」などを条件に加えられる。

CSVの `actual_difficulty` はその組織で実際に起きた問題を示し、想定・引用・否定文は含まない。`resolved` は実際に起きた問題を解決した記事だけが1。`resolved=0` だけでは未解決とは限らない。

## 試す検索例

最初は話題を限定した条件から試すと、候補取得とJevの判定の違いを見やすい。

| 検索条件 | 全データ中の想定該当数 |
| --- | ---: |
| 国産クラウドへのサイト移行で、実際に運用を始めてから困ったことが書かれている記事 | 20 |
| 国産クラウドへのサイト移行で実際に困ったことがあり、料金や費用には一切言及していない記事 | 15 |
| 国産クラウドを導入して問題なく運用できており、料金や費用に言及していない記事 | 10 |
| Movable Typeの承認フローを導入した後に承認が滞ったが、対処して解決した事例 | 15 |
| バックアップから画像を復元できず、まだ解決していない事例 | 5 |
| 担当者が5人以下で、国産クラウドへの移行後の問題を解決した事例 | 3 |

たとえば2番目の条件の想定該当記事は、`JEV-0006〜0010`、`JEV-0036〜0040`、`JEV-0041〜0045`。3番目の条件では `JEV-0011` が該当し、本文末尾に料金を足した `JEV-0031` は該当しない。

`queries.json` にはこのほか、料金を理由に導入を見送った記事、不在条件だけの検索、実際の問題と想定・引用の区別も入っている。

件数は作成した文章の意味から定義した**全1,000件中の想定値**であり、実APIで測定した結果ではない。現在の検索はembedding上位50件の中で判定するため、候補漏れやモデルの判断によって結果は変わる。特に不在条件だけの検索は想定600件あり、既定の候補数では全件を返せない。

## 検証と再生成

MT9の標準 `MT::ImportExport` と一時SQLite DBで、全1,000件のインポート、全件下書き、20カテゴリー、BODYの日本語・HTMLの完全一致、他本文欄が空であることを確認した。検証で外部APIを呼んでいない。

生成スクリプトは本文の重複がないこと、料金の記載とCSVのフラグが一致することも検証する。再生成する場合は次を実行する。

```sh
python3 specs/demo-data/generate_dataset.py
```

生成ファイルは同じ名前で上書きされる。MTへの再インポートは既存記事の更新用ではなく、記事の追加になる。
