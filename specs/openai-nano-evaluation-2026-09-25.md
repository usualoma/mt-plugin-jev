# GPT-5.4 nano の1記事ずつの判定と推論負荷の比較

実施日: 2026-09-25

## 結論

今回のデータと検索文では、`gpt-5.4-mini` / `none` が3回とも想定上の正解7件だけを採用した。`gpt-5.4-nano` は1記事ずつでも `none` では条件違反の記事を採用し、`medium` / `high` では誤採用がなくなった一方、正解の取りこぼしが発生した。`high` は `medium` より取りこぼしと採否の変動が多く、推論負荷を上げるだけでは解決しなかった。

現時点では、この検索の設定は mini / none を維持するのがよさそう。nano / medium は費用を下げる候補にはなるが、今回の結果から同等の精度・安定性とは評価できない。プラグイン本体やMTの保存済み設定は、この試験では変更していない。

## 条件

- 検索文: 「ちいさくてかわいいやつに関する感想で、好意的なもの。映画を対象にしたもののみ。ネタバレを含まない」
- 対象: 前回と同じ `CKW-0001`〜`CKW-0050` の50記事。各設定を3回ずつ、計600回のAPIリクエストで評価した。
- 元データ: `1298be1^` の `specs/demo-data/chiikawa/`。一時ファイルのタイトル・本文が元データに存在し、分類ラベルが元の manifest と一致することを確認した。削除済みデータセットはリポジトリに復元していない。
- 正解ラベル: manifest の「映画・肯定的・ネタバレなし」の組み合わせ。該当は7記事。50記事の内訳は映画26／TV24、肯定27／否定23、ネタバレあり25／なし25。
- 入力: タイトルと全文BODY。本体の `Content::plain_text` でHTMLを除去した。正解ラベルはAPIに渡していない。ネタバレありの25記事すべてに本文中の「ネタバレ注意」があり、残りの25記事にはないことを確認した。
- API: Responses API。モデル指定は `gpt-5.4-mini` / `gpt-5.4-nano`。実際の応答モデルは、それぞれ `gpt-5.4-mini-2026-03-17` / `gpt-5.4-nano-2026-03-17`。
- 共通設定: 1記事ずつ、10並列、しきい値0.5、`max_output_tokens: 8192`、`store: false`。全12試行で実測最大並列数は10だった。
- 本体の `OpenAIEvaluator` と `evaluate_batches` を利用。試験用サブクラスで `reasoning.effort` だけを切り替え、`none` では両モデルとも `temperature: 0`、`medium` / `high` では `temperature` を省略した。判定指示文・JSONスキーマ・記事順は共通。
- 現行の本体ではnanoに `temperature` を明示しないため、今回のnano / noneは「モデル名だけを変更した場合」とは設定が異なる。
- 4設定の実行順を各周回で1つずつずらし、試行同士は重ねずに実行。リクエスト上限60秒・検索上限180秒は本体の設定を使用し、全試行が完了した。

時間はワーカー起動・HTTP通信・API判定・応答処理・ワーカー回収を含む。検索文のembedding、DB取得、ベクトル検索、画面生成は含まない。embeddingで候補を選ぶ工程も再現していない。

## 結果

誤採用・取りこぼし・採用件数は、1回目／2回目／3回目の順。時間と費用は各3回の中央値で、50記事を1件ずつ判定する1試行あたりの値。

| モデル / 推論負荷 | 採用件数 | 誤採用 | 正解7件の取りこぼし | 時間（中央値） | 概算費用（中央値） |
| --- | --- | --- | --- | ---: | ---: |
| mini / none | 7 / 7 / 7 | 0 / 0 / 0 | 0 / 0 / 0 | 6.50秒 | 5.26円 |
| nano / none | 14 / 13 / 15 | 7 / 6 / 8 | 0 / 0 / 0 | 6.13秒 | 1.41円 |
| nano / medium | 5 / 7 / 6 | 0 / 0 / 0 | 2 / 0 / 1 | 11.72秒 | 3.03円 |
| nano / high | 5 / 2 / 6 | 0 / 0 / 0 | 2 / 5 / 1 | 14.89秒 | 3.58円 |

「ネタバレ注意」がある記事の誤採用は、全設定・全試行で0件だった。nano / none の誤採用は、TV版の肯定的な感想と、映画の否定的な感想だった。ネタバレの除外ができても、「映画のみ」「好意的」という条件をすべて満たせるとは限らなかった。

同じ記事について、3回の間に採否が変わった件数は mini / none が0件、nano / none が2件、nano / medium が3件、nano / high が6件。これはしきい値0.5での採否の比較であり、関連度スコアや表示順位の完全一致を意味しない。

推論量を増やすとnanoでも出力課金が増え、今回のmediumはmini / noneの約58%、highは約68%の費用になった。時間はそれぞれ約1.8倍、約2.3倍だった。

今回の短いダミー記事では、指示文等を含めたAPI入力が1リクエスト平均約731トークンであり、「1記事5,000トークン」の試算とは異なる。長い記事の精度・推論量・時間・費用を、この試験だけから推定することはできない。費用には検索時のembedding生成や記事の事前embedding生成を含めていない。

## 解釈の範囲と記録

50種類の記事・1つの検索文を各3回で比べた小規模な実測。正解はダミーデータ作成時の分類ラベルに基づき、モデルから不一致理由は取得していない。とくに「ネタバレなし」の記事にも導入のあらすじがあり、ネタバレの範囲には解釈の余地がある。取りこぼしの内部原因や、他の検索文・実記事での性能は断定しない。

API使用量の集計値が全リクエストの合計と一致すること、各試行50件の応答が揃ったことを確認した。[生の計測値と集計結果](openai-nano-evaluation-2026-09-25.json)には各記事のスコア、採否、リクエスト時間、入力・出力・推論トークン数、実際の応答モデル、実装のハッシュを記録した。APIキー・記事本文・モデルの推論本文は含めていない。

推論負荷の対応範囲は[GPT-5.4 nanoの公式仕様](https://developers.openai.com/api/docs/models/gpt-5.4-nano)、推論トークンの課金方法は[Reasoning models](https://developers.openai.com/api/docs/guides/reasoning#how-reasoning-works)を参照。
